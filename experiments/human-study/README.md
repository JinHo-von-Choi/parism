# 사람 실험 (5~8명) — 아직 실행되지 않았다

계획서 10장의 남은 절반이다. 기계 하네스가 **기계적으로 채점 가능한 것만** 재는 사이,
사람이 매기는 나머지를 담기 위한 절차다.

## **여기에는 결과가 없다**

이 디렉터리에는 **과제와 채점 규칙만** 있다. 실측한 사람이 0명이다.
`scoringsheet.csv` 는 빈 템플릿이고, 채우기 전까지 어떤 결론도 읽을 수 없다.

자동으로 채우지 않는다. 지워서 다시 만드는 것도 아니다. 사람이 직접 채운다.

## 파일

| 파일 | 무엇인가 |
|---|---|
| `PROCEDURE.md` | 참가자 모집, 고정할 값, 진행 순서, **하지 말아야 할 것**, 결과를 어떻게 읽는지 |
| `TASKS.md` | 과제 30개(6묶음 × 5). 고정 프롬프트·기대값·채점 규칙 |
| `scoringsheet.csv` | 기록 시트 템플릿. 사람이 4개 열만 채운다 |
| `analyze.mjs` | 원시 집계와 신뢰구간. **판정하지 않는다** |

## 설계에서 일부러 택한 것

**기계 채점과 사람 채점을 분리한다.** `correct` 와 `wrong_kind` 는 기계가 원문과 바이트로
대조해 채운다. 사람이 채점한 것을 쓰지 않는다. 사람이 "맞았다"고 쓰는 순간 그건
정답이 아니라 사람의 확신이고, 둘이 다를 때를 알아야 한다.

**오답보다 무거운 실패를 따로 센다.** `fabricated_evidence`(맞는 값을 주되 근거가 거짓)와
`silent_loss`(빠진 것에 사유 없음)는 오답 목록에 묻지 않는다. 근거가 거짓이면 사람은
"맞았다"고 믿고 넘어가기 때문이다. 이 도구의 존재 이유가 무너지는 지점이다.

**거절 사유를 4과제로 나눈다.** `unknown_id`(모르는 id)·`not_retained`(처음부터 보관 안 함)·
`expired`(만료)·`evicted`(퇴출)는 **전부 "실패" 가 아니라 서로 다른 실패**다. 뭉뚱그리면
사용자가 "다시 시도하면 되나, 처음부터 안 된 건가" 를 알 수 없다.

**환경을 고정한다.** 모델·버전·온도(0)·프롬프트를 글자 그대로. 하나라도 흔들리면
"parism 이 나았다"가 아니라 "그 모델이 그날 좋았다"가 된다.

**팔 순서를 참가자마다 교대한다.** 항상 A→B면 두 번째 팔이 첫 번째의 기억을 이긴다.

**5회 반복한다.** 온도 0이어도 완전 결정론은 아니다. 1회로 재면 그 운을 측정한다.

## 이 실험이 하지 않는 판정

**유의성 검정을 하지 않는다.** 5~8명으로는 할 수 없다. 신뢰구간을 붙이되 그것이
유의성은 아니라고 문서에 적었다. 구간을 붙이는 이유는 "점 하나가 아니라 범위로 읽어야 한다"를
강제하기 위해서다.

**n < 5 면 구간을 내지 않는다.** 숫자를 억지로 내지 않는다.

**평균을 쓰지 않는다.** 시도 횟수와 확인 시간은 분포를 보고 중앙값과 p90 을 쓴다.
3명이 5분씩 멈춰 서 있었다면 평균은 그 3명에 지배된다.

## 실행 순서

```bash
# 1. 과제 fixture 를 참가자별로 준비한다 (서로의 것을 보면 안 된다)
# 2. 각 참가자에게 1~6장 순서로 진행한다 (절차서 7장)
# 3. 사람이 4개 열을 채운다: attempts, verify_seconds, gave_up, reason
# 4. correct / wrong_kind 는 기계가 채운다 (절차서 6장)

node experiments/human-study/analyze.mjs experiments/human-study/scoringsheet.csv
```

## 읽는 법 (절차서 10장)

결과는 세 가지 중 하나일 가능성이 높고 **어느 쪽이든 publication 은 아니다**:

1. **B 가 정확도에서 이겼다** — 근거 없는 답을 줄였다는 것, 이 도구의 존재 이유다.
   **확인 시간도 줄었다는 별도 증거가 있어야** "더 빠르다"고 말할 수 있다.
2. **정확도는 같고 확인 시간만 줄었다** — 쓸 만한 이유지만 작은 이유다.
3. **차이가 없다** — **이 실험이 실패한 것이지 도구가 실패한 것이 아니다.**
   왜 안 나왔는지를 봐야 한다(과제 난이도가 낮았거나, 참가자가 쓰임새를 못 찾았거나).
   이 경우 설계를 고쳐 다시 해야 한다.

3번을 "도구가 별로다"로 읽으면 안 된다. **무엇이 안 나왔는지가 다음에 할 일이다.**
