# ADR: MCP 결과 첫 줄에 cwd 배너를 붙인다

- **작성자**: 최진호
- **작성일**: 2026-10-22
- **수정일**: 2026-10-22
- **상태**: 채택, 구현 완료 (v2.2.0)

## 맥락

MCP 도구(`run`, `run_paged`) 의 결과는 작업 디렉터리에서 실행한 결과다. 그런데 결과에는 **어느 디렉터리에서 실행됐는지**가 드러나지 않는다.

`ResponseEnvelope.cwd` 에는 값이 들어 있다. 하지만 두 가지 문제가 있다.

1. 그 필드는 **결과 JSON 안쪽 깊은 자리에** 있다. 실패 응답을 먼저 읽고 멈추는 에이전트는 그 필드를 보지 않는다.
2. 상대 경로 출력이 섞이면 무엇이 어느 것인지 알 수 없다. `src/config/loader.ts` 가 파일이다 해도, 어느 경로의 `src` 인지는 결과만 보고는 결정되지 않는다.

에이전트가 "어디서 실행됐는지" 모르면 후속 판단이 전부 불확실해진다. 같은 명령을 다른 위치에서 다시 실행하면 다른 결과가 나오고, 그 차이를 해석할 근거가 없다.

## 결정

### 1. 결과 텍스트의 첫 줄에 배너를 붙인다

```
[cwd] /home/user/project

{
  "ok": true,
  ...
}
```

- 배너는 `[cwd] ` 로 시작하는 한 줄이다.
- 배너 뒤에 **빈 줄 하나**를 둔다. 배너와 JSON 의 경계가 눈에 보여야 한다.
- 경로는 **절대 경로**다. 심볼릭 링크를 따라 확정한 실제 경로를 쓴다.

### 2. 명령을 실행하는 도구에만 붙인다

| 도구 | 배너 | 이유 |
|------|------|------|
| `run` | 예 | 명령을 실행한다 |
| `run_paged` | 예 | 명령을 실행한다 |
| `describe` | 아니오 | 실행하지 않는다 |
| `dry_run` | 아니오 | 실행하지 않는다 |
| `compare_results` | 아니오 | 저장된 결과를 비교한다 |
| `explain_result` | 아니오 | 저장된 결과의 근거를 본다 |
| `fetch_result` | 아니오 | 저장된 결과의 다음 페이지를 본다 |

**실행하지 않는 도구에 배너를 붙이면 의미가 없다.** 거기서 작업 디렉터리는 이미 정해져 있다.

### 3. 배너는 계약 변경이다 — JSON 으로만 읽을 수 없다

배너가 붙으면 도구 결과 텍스트가 **순수한 JSON 이 아니게 된다.** `JSON.parse(text)` 를 바로 쓰는 소비자는 앞의 두 줄을 먼저 빼야 한다.

이건 의도한 변경이다. `cwd` 를 JSON 안에만 숨기는 대안보다 앞쪽에 두는 편이 "어디서 실행됐는지" 를 즉시 보이게 한다. 그 대가는 소비자가 두 줄을 빼야 하는 것이고, **MCP 도구 설명과 README 에 그 방법을 적는다.**

이 저장소의 시험도 함께 고쳤다(`tests/server-tools.test.ts`). 계약 변경을 하면 시험이 함께 바뀌어야 한다. 시험을 바꾸지 않고 계약을 바꾸면 둘 중 하나가 거짓말이 된다.

## 이 결정이 주는 것과 주지 않는 것

**주는 것**: 결과의 첫 줄에서 작업 디렉터리를 즉시 안다. JSON 안을 파고들지 않아도 된다. 상대 경로 출력을 해석할 때 기준점이 생긴다.

**주지 않는 것**:

- **배너는 명령이 실행된 디렉터리다.** guard 가 허용 경로 밖을 막았다면 명령은 실행되지 않았고, 배너는 요청한 cwd 다.
- **결과 텍스트가 순수 JSON 이 아니다.** 파싱 전에 두 줄을 빼야 한다.
- **디렉터리의 내용을 알려주지 않는다.** 그건 `ls` 로 따로 보면 된다.

## 대안

- **JSON 안에만 `cwd` 를 둔다 (기각)**: 이미 있다. 그런데 실패 응답을 먼저 읽는 에이전트가 그 필드를 보지 않는다. 필드가 있어도 안 보이면 정보가 아니다.
- **JSON 의 맨 위에 `cwd` 를 새로 넣는다 (기각)**: `ResponseEnvelope.cwd` 와 중복이다. 같은 사실을 두 자리에 두면 어느 쪽이 authoritative 인지 모른다.
- **별도 content 블록으로 배너를 낸다 (기각)**: MCP content 배열에 두 번째 항목을 넣으면 소비자가 `content[0]` 만 읽을 때 배너를 놓친다. 화면에는 두 블록이 따로 보이고, 어느 쪽이 결과인지 헷갈린다.
- **배너를 넣지 않는다 (기각)**: 상대 경로 결과의 해석 근거가 없는 상태로 남는다.

## 결과

- `run` 과 `run_paged` 의 결과 텍스트가 `[cwd] <절대경로>` + 빈 줄 + JSON 형태가 된다.
- MCP 도구 설명에 "첫 두 줄을 빼고 JSON 파싱하라" 고 적었다.
- 이 저장소의 MCP 시험이 배너를 aware 하도록 바뀌었다.
