# ADR: 네이티브 정규식 엔진 — 역추적 불가능성과 바이트 동일성

- **작성자**: 최진호
- **작성일**: 2026-10-22
- **수정일**: 2026-10-22
- **상태**: 채택, 구현 완료

## 맥락

parism 은 사용자가 준 정규식 패턴을 그대로 실행한다. 그 패턴은 `redactor`·`mask-map`·`sanitize` 세 곳을 지나 출력 바이트에 영향을 준다. 즉 **사용자 제공 패턴이 출력의 비밀 가림 여부를 결정한다.**

지금 쓰는 정규식 엔진은 V8 의 역추적 엔진이다. 역추적 엔진은 catastrophic backtracking 에 취약하다. `(a+)+$` 에 `a` 를 32개 붙인 문자열 하나로 JS 는 **93,534ms** 를 쓴다(실측). 서버 프로세스 하나가 그 패턴 하나에 93초를 내주면 그건 서비스 중단이다.

이 문제를 풀려면 정규식 엔진이 **선형 시간**을 보장해야 한다. Rust 의 `regex` 크레이트가 그 조건을 만족한다(역추적 불가능).

그런데 엔진 교체는 성능 변경이 아니다. **출력이 바뀌는 변경**이다. 정규식 엔진이 달라지면 어떤 패턴이 더 많이, 어떤 패턴이 더 적게 매칭될 수 있다. 그리고 매칭이 달라지면 **가려지는 구간이 달라진다.** 가려지지 않은 비밀은 가려진 것처럼 보인다. 이건 계약 위반이 아니라 **안전 사건**이다.

그래서 이 결정의 핵심은 성능이 아니다. **"같은 결과를 낸다" 를 어떻게 증명하느냐** 다.

여기서 한 가지 위험이 있다. **검증 자체가 거짓말을 할 수 있다.** 두 엔진의 출력이 원래부터 같으면 — 즉 비교할 것이 없으면 — 비교는 "통과" 한다. 그러면 Rust 를 한 번도 안 돌렸는데도 "바이트 동일성 검증 완료" 라고 말할 수 있다. 통과한 것이 아니라 **비교할 것이 없었다** 는 뜻인데, nobody notices it.

이 ADR 의 결정 6 은 이 함정을 막는 규칙이다.

## 결정

### 1. 정규식 안전성만 Rust 로 옮긴다. 나머지는 TypeScript 에 둔다

`src/` 의 정적 정규식 리터럴 181건(실측)은 옮기지 않는다. 역추적 위험은 **사용자 제공 패턴**에서만 발생한다. 정적 리터럴은 Rust 로 옮길 이득이 없고 계약 변경 위험만 늘어난다.

옮기는 것은 **동적 `new RegExp(...)` 3곳**뿐이다 — `src/engine/redactor.ts`, `src/engine/mask-map.ts`, `src/fixtures/sanitize.ts`.

### 2. 네이티브 애드온이 아니라 **프로세스**로 돌린다

Node 네이티브 애드온(napi)이면 호출이 빠르지만 빌드 도구체인을 요구하고 크로스 빌드 매트릭스를 따라야 한다. 프로세스는 **사전 빌드된 바이너리 하나**로 끝나고 어떤 플랫폼에서든 같은 방식으로 돌아간다.

프로세스는 호출마다 IPC 비용이 있다. 측정 결과는 이, 여러 작업이 모이면 상쇄된다.

### 3. 프로토콜은 JSON 이 아니라 **길이 프레이밍**이다

JSON 으로 주고받으면 `serde_json` 의존이 필요하다. 그러면 "의존성은 `regex` 하나" 라는 원칙이 깨진다. 프로토콜은 손으로 정의한 길이 프레이밍이다.

```
요청: op u8 | id u32 | count u32 | pattern×count(u32+bytes) | text(u32+bytes)
      | replacement(u32+bytes) | literal u8
응답: [u32 총길이] | status u8 | id u32 | kind u8 | message(u32+bytes) | payload
```

### 4. JavaScript 와 Rust 의 의미 차이를 **알고 찾아서 없앤다**. 못 없애는 것은 **전부 되돌린다**

두 엔진은 같은 문법이 같은 의미가 아니다. 실측한 차이는 이렇다.

| 표현 | JavaScript | Rust | 처리 |
|------|-----------|------|------|
| `\b` | ASCII 단어경계 | 유니코드 단어경계 | `(?-u:\b)` 로 옮긴다 |
| `\d` `\w` | ASCII | 유니코드 | `(?-u:\d)` `(?-u:\w)` 로 옮긴다 |
| `\s` | +U+FEFF, −U+0085 | 유니코드 화이트스페이스 | JavaScript 의 집합을 **명시**한다 |
| `.` (s 플래그 없음) | −\n\r\u2028\u2029 | −\n | `[^\n\r\u2028\u2029]` 로 옮긴다 |
| `i` 플래그 | ECMA-262 정규화 | 유니코드 단순 폴딩 | **되돌린다** |
| `m` 플래그 | \n\r\u2028\u2029 | \n | **되돌린다** |
| lookaround·역참조 | 지원 | 미지원 | **되돌린다** |
| 빈 매칭 직후 | JS 는 생성 | Rust 는 건너뜀 | `replace_all_js` 로 재현한다 |

`i` 플래그를 되돌리는 이유는 실측으로 정했다. U+017F(ſ)와 U+212A(K)는 **ECMA-262 정규화와 Rust 단순 폴딩이 처음 갈리는 지점**이다. ECMAScript 는 정규화(ſ→s, K→k)하고 Rust 은 폴딩만 한다. 유니코드 폴딩을 그대로 쓰면 `ſecret` 가 `secret` 에서 가려지지 않는다.

**되돌린다는 것은 "조용히 비슷한 것으로 바꾸지 않는다" 는 뜻이다.** 사유를 함께 기록한다.

### 5. 되돌아간 사실은 `failure` 가 아니라 **결과 메타데이터**로 남긴다

`FailureInfo` 의 `kind` 와 `reason` 은 바꾸지 않는다(기존 값 보존). 되돌아간 사실은 `envelope.regex_engine` 에 남는다.

```json
{ "regex_engine": { "used": "typescript", "fallbacks": [
  { "pattern": "…", "reason": "the i flag uses ECMA-262 Canonicalize, …" }
] } }
```

실패가 아니라 **메타데이터**다. 정규식이 동작했는데, Rust 가 못 해서 TypeScript 가 대신했다. 그 사실은 소비자가 알 수 있어야 하고, 서버가 실패한 게 아니므로 실패로 표시하면 안 된다.

### 6. 바이트 동일성 게이트 — **그리고 "비교할 것이 없는 통과" 를 막는 규칙**

검증은 두 엔진의 출력을 **바이트로** 비교한다. 비교 대상은 세 층위다.

1. **파이프라인 층위** — `redact`·`maskWithRanges`·`sanitizeText` 의 결과. 텍스트뿐 아니라 **구간과 리댁션 기록**도 비교한다. 구간이 틀리면 근거 바이트 구간이 틀어지므로 그 결과가 조용히 나간다.
2. **엔진 층위** — 패턴 × 텍스트 조합에서 `findAllRanges` 와 `replaceAllText` 를 직접 비교한다.
3. **코퍼스 층위** — `parism test` 가 되짚는 **바로 그** 파서 팩 fixture(27건 / 2,591바이트) + manifest fixture.

그리고 규칙이 하나 더 있다.

> **`rustEngaged` 와 `redactions` 가 0 이면 통과가 아니라 검증 실패다.**
>
> `rustEngaged` — Rust 엔진이 실제로 처리한 연산 수.
> `redactions` — 실제로 뭔가를 가린 횟수.
>
> 코퍼스 27 fixture / 2,591 바이트에 기본 리댁션 패턴이 **한 번도 걸리지 않는다**(실측).
> 원본만 비교하면 두 결과가 처음부터 같아서 통과한다.
> 그래서 비밀 형태 문자열을 섞은 **파생 항목**을 함께 비교한다. 원본 계약은 건드리지 않는다.

CI 는 `PARISM_REQUIRE_NATIVE=1` 로 이 게이트를 건다 — Rust 바이너리가 없으면 **실패**한다.

### 7. 엔진이 고장 나면 서버가 죽지 않는다

엔진은 외부 프로세스다. 언제 죽을지 모른다. 그래서 세 가지 실패를 모두 다룬다.

| 상황 | 처리 |
|------|------|
| 프로세스가 죽었다 | 대기 중인 요청을 실패로 돌리고 TypeScript 로 되돌린다 |
| **잘린 프레임** 이 왔다 | 프레임 길이를 검증해 **명확한 오류** 로 바꾼다 |
| **침묵한다** (응답이 안 온다) | 요청 제한 시간(기본 10초)을 넘으면 실패로 돌린다 |

세 번째는 실측으로 넣었다. 잘린 프레임을 보낸 엔진이 입력을 더 읽지 않으면 요청은 영영 끝나지 않는다. 그때 **그 요청만** 멈춘다 — 서버 전체는 살아 있어야 한다.

### 8. npm 플랫폼 패키지 8종 + `optionalDependencies`

`@nerdvana/parism-regex-{darwin-arm64,darwin-x64,linux-x64-gnu,linux-x64-musl,linux-arm64-gnu,linux-arm64-musl,win32-x64-msvc,win32-ia32-msvc}` 8종을 만든다. 각 패키지는 **사전 빌드된 바이너리 하나**와 `os`·`cpu`·`libc` 게이팅 필드만 갖는다.

메인 패키지는 이들을 `optionalDependencies` 로 참조한다. **`postinstall` 도 확인 스크립트도 넣지 않는다.** 게이팅은 npm 이 자체적으로 한다 — 설치가 실패해도 조용히 넘어가야 하는 이유가 없다.

플랫폼 패키지 목록은 `scripts/native-platforms.mjs` 한 파일에서 만든다. 이름·Cargo 타깃·게이팅 필드 셋 중 하나라도 어긋나면 **조용히** 그 호스트에서 엔진이 사라진다.

## 이 결정이 주는 것과 주지 않는 것

**주는 것**: 사용자 제공 패턴이 역추적 폭탄이어도 서버가 멈추지 않는다. Rust 엔진이 같은 결과를 내지 못하는 패턴은 **사유와 함께** TypeScript 로 되돌아가고, 그 사실이 결과에 남는다. 출력 바이트가 바뀌지 않는다는 것을 **재현 가능한 측정값**으로 증명한다(2,886건 비교 / 불일치 0건).

**주지 않는 것**:

- **이 엔진은 파서를 파싱하지 않는다.** 정규식만 담당한다. 파서의 계약은 그대로다.
- **Rust 엔진이 없으면 조용히 TypeScript 로 내려간다.** 출력은 같지만 **성능 이득이 없다.** 되돌아간 사실은 기록되지만, 엔진이 아예 없는 환경에서는 기록조차 안 남을 수 있다 — 그래서 `rustEngaged` 를 CI 게이트로 잡았다.
- **역추적 폭탄을 막아도 정규식 자체의 오류를 막지는 못한다.** 잘못된 패턴은 여전히 오답이다.
- **`i`·`m`·`u`·`y` 플래그 패턴은 Rust 를 쓰지 않는다.** 성능 이득이 없는 대신 정확성은 TypeScript 에 맡긴다.
- **이 결정은 Phase 4 의 Wasm 샌드박스를 대체하지 않는다.** 정규식 안전성과 **서드파티 코드 격리**는 다른 문제다.
- **프로세스 경계는 보안 경계가 아니다.** 엔진 프로세스는 parism 과 같은 권한으로 돈다.

## 대안

- **Rust 로 전면 재작성 (기각)**: 정규식 안전성 + Wasm 샌드박스 두 곳만 필요하다. 파서를 Rust 로 옮기면 출력 바이트 동일성 보장이 어려워지고, 이득은 없다.
- **Node 네이티브 애드온(napi) (기각)**: 호출이 빠르지만 빌드 도구체인을 요구하고 크로스 빌드 매트릭스를 따라야 한다. 프로세스 하나면 끝난다.
- **`serde_json` 으로 프로토콜 (기각)**: 읽기 쉽지만 의존성이 늘어난다. "의존성은 `regex` 하나" 라는 원칙이 깨진다. 길이 프레이밍은 손으로 100줄이고 검증된다.
- **JSON 으로 응답 주고 TypeScript 에서 파싱 (기각)**: 응답을 받는 쪽이 매번 JSON 파서를 돌려야 한다. 파싱 실패가 프로토콜 오류로 보이지 않는다.
- **`i` 플래그를 Rust 유니코드 폴딩으로 옮긴다 (기각)**: U+017F·U+212A 에서 결과가 갈린다(실측). `ſecret` 가 안 가려진다.
- **되돌릴 때 사유를 남기지 않는다 (기각)**: 조용히 바뀌면 나중에 "무엇이 왜 바뀌었는지" 를 알 수 없다.
- **정적 정규식 181건도 Rust 로 옮긴다 (기각)**: 이득이 없고 계약 변경 위험만 늘어난다.
- **엔진 실패를 조용히 통과시킨다 (기각)**: "Rust 가 이 패턴을 못 한다" 와 "Rust 가 죽었다" 를 구별할 수 없다. 구별 못 하면 다음에도 같은 진단을 반복한다.
- **플랫폼 패키지를 `postinstall` 로 받는다 (기각)**: 설치가 실행 코드를 돌리게 된다. 게이팅 필드로 충분하다.
- **JSON 프로토콜을 유지한다 (기각)**: 의존성이 늘고, 실패 모드(잘린 프레임)가 "파싱 에러" 로 뭉개진다.

## 결과

### 구현

- `crates/parism-regex/` — edition 2024, MSRV 1.89, `regex` 크레이트만 의존. lib + bin. release 바이너리 1.5MB.
- `src/engine/regex-native.ts` — 지속 프로세스, 길이 프레이밍, 요청 제한 시간, 실패 분류.
- `src/engine/regex-engine.ts` — 패턴 번역, 엔진 선택, 폴백 기록, 바이트↔UTF-16 좌표 변환.
- `src/engine/regex-byte-identity.ts` — 바이트 동일성 검증 하네스. **무의미한 통과를 막는 지표**를 함께 낸다.
- `packages/parism-regex-*/` — 8종 플랫폼 패키지. `scripts/native-platforms.mjs` 가 만든다.
- `.github/workflows/native-regex.yml` — Rust 엔진 활성 상태의 바이트 동일성 게이트 + 8종 크로스 빌드 + 플랫폼 패키지 게시.

### 구현 중 발견한 결함 5건 (모두 수정)

1. **폴백 사유가 거짓이었다.** `replaceAllText` 가 치환 문자열에 `$` 가 있거나 빈 매칭 순서를 재현할 수 없을 때 TypeScript 로 되돌아가는데, 그 뒤 "바이너리가 없습니다" 라는 **거짓 사유**가 추가로 기록되었다. 사유는 사실이어야 한다 — 근거로 쓰는 값이니까.
2. **네이티브 프로세스가 CLI 의 종료를 막았다.** `child.unref()` 는 **프로세스 핸들** 만 놓아 준다. stdio 파이프가 이벤트 루프를 붙잡아서, `parism capture` 같은 명령이 결과를 찍고도 멈춰 서 있었다. 요청이 떠 있는 동안만 붙잡도록 바꿨다.
3. **잘린 프레임이 Node 를 죽였다.** 길이 검증 없이 읽다가 `readUInt8` 가 범위를 벗어나 예외를 던졌고, 그 예외는 stdout 의 `data` 핸들러 안에서 났다 — **Node 프로세스 전체가 죽었다.** 프레임 길이 검증과 명확한 오류로 바꿨다.
4. **`[\b]` 번역이 깨졌다.** 문자 클래스 첫 글자 자리에 이스케이프가 오면 표시가 지워지지 않아 `[\b]` 가 "닫히지 않은 클래스" 로 잘못 판정되었다. Rust 가 **올바른 패턴을 거절**하고 있었다. 안전하지만 낭비였다.
5. **엔진이 침묵하면 요청이 영영 끝나지 않았다.** 잘린 프레임을 보내고 멈춘 엔진 앞에서 그 요청만 멈췄다. 요청 제한 시간(기본 10초, `PARISM_REGEX_TIMEOUT_MS` 로 조정)을 넣었다.

### 남는 것

- 플랫폼 패키지 8종의 **실제 크로스 빌드와 게시는 아직 하지 않았다.** 워크플로는 작성했지만 이 호스트에서는 linux-x64-gnu 하나만 만들 수 있다. 나머지 7종은 CI 를 돌려야 확인된다.
- npm 로컬 인증이 없다. 게시는 CI OIDC 경로로만 된다.
