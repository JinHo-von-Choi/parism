# ADR: 의미 diff의 identity 규칙과 "거짓 삭제 0"

- **작성자**: 최진호
- **작성일**: 2026-10-22
- **수정일**: 2026-10-22
- **상태**: 채택, 구현 완료 (v2.1.0)

## 맥락

`compare_results` 는 **이미 존재하는 두 결과**를 비교한다. 새 명령을 실행하지 않고, 원격에 접속하지 않고, 감시 루프를 만들지 않는다. 그 자체가 설계 기제였다 — "재시도율" 이라는 이름이 붙은 시나리오는 실제로 재시도를 한 번도 세지 않았다.

문제는 **두 결과를 줄여놓고 뺄셈을 하는 것**이다. 줄인 결과(`stdout.parsed`)만 놓고 비교하면, 줄이는 과정에서 빠진 값을 "삭제된 것"으로 오인한다. 파서가 일부 출력을 못 읽은 경우, 출력이 잘린 경우, 표시 변환이 값을 잃은 경우 — 이 셋 모두 **결과가 불완전하다**는 뜻이지 **무언가 사라졌다**는 뜻이 아니다.

여기에 결정이 갈라졌다. 불완전한 결과를 **강제로 비교하면** 다음과 같은 일이 생긴다.

- 절단된 출력을 "삭제"로 보고한다 → 실제로는 원래 거기에 있었다
- 파서가 못 읽은 영역을 "삭제"로 보고한다 → 파서的能力 밖일 뿐이다
- PID 를 identity 로 삼아, 재사용된 PID 를 "추가"와 "삭제"로 보고한다 → 같은 자원이었다

**잘못된 결론이 조용한 실패보다 나쁘다.** 비교 도구의 존재 이유가 "무엇이 바뀌었는지 아는 것" 이라면, 거짓 삭제는 그 도구를 못 쓰게 만든다.

## 결정

### 1. 지문(fingerprint)으로 비교 가능성을 먼저 판정한다

두 결과의 지문(`src/engine/compare/fingerprint.ts`)을 비교해 호환성을 **네 등급**으로 나눈다: `same` / `compatible` / `unknown` / `incompatible`.

- OS 나 파서 버전이 달라졌다고 모든 비교를 막지 않는다.
- **판단할 수 없으면 `unknown`** 이고, strict 비교는 거절한다.

지문에는 `cmd`, argv 해시, 실제 작업 디렉터리, 가드 정책 해시, 파서·스키마·내용 해시, 플랫폼, 선택된 도구 버전, locale, 사용자가 명시한 문맥이 들어간다.

**지문은 세계 상태를 캡처한 인증서가 아니다** — 같은 지문이어도 그 사이 파일이 바뀌었을 수 있다. 그래서 지문은 *비교 가능한지*를 정하는 근거이지 *같다는 증거*가 아니다.

### 2. argv 와 환경 변수를 다르게 취급한다

- **argv 는 해시로 식별하고**, 표시에는 마스킹한 값만 쓴다.
- **환경 변수는 '이름'만 관찰 기록에 남기고 값은 담지 않는다.** 관찰 기록은 동일성 비교 키에 들어가지 않는다.

### 3. identity 규칙은 도메인마다 다르다

| 도메인 | identity |
|--------|----------|
| git | 저장소 identity(실경로) + 정규 경로. 이름 변경은 **확정 정보**(원래 경로)가 있을 때만 연결 |
| kubernetes | context/namespace/kind + `metadata.uid` |
| ps | **PID 만을 identity 로 삼지 않는다** |

kubernetes에서 **uid 없는 표 출력으로는 같은 자원이라고 말하지 않는다** — 재생성된 같은 이름과 구분이 안 된다. ps에서 PID 재사용은 **일반적인 현상**이라 PID 비교는 **보류**한다. 둘 다 "모르겠다" 를 "달라졌다" 로 말하지 않기 위한 규칙이다.

### 4. 거짓 삭제 0 — 불완전하면 삭제로 단정하지 않는다

어느 한쪽이라도 불완전하면(수집 잘림·파서 실패·표현 손실) 없는 행을 '삭제'로 단정하지 않고 `partial.withheld_reasons` 에 보류를 남긴다. identity 를 확정하지 못한 행이 있어도 '추가'나 '삭제'로 단정하지 않는다.

**못 찾았다고 새로 생긴 것이 아니다.**

### 5. 중복 identity 는 조용히 정리하지 않는다

중복 identity 가 있으면 오류다(`duplicate_identity`). 한 행을 임의로 버리지 않는다 — 어느 행을 버릴지 판단할 근거가 없다.

### 6. 비교에 쓸 수 있는 행이 아니면 비교를 거절한다

두 결과 중 하나라도 보관되지 않았거나, 지문이 없거나, 출력이 불완전하면 **비교를 진행하지 않고 사유를 함께 돌려준다**. 아무것도 비교 안 하고 "변화 없음" 이라고 말하지 않는다.

## 이 결정이 주는 것과 주지 않는 것

**주는 것**: 비교 결과의 모든 문장이 관측에 근거한다. "삭제" 는 실제로 사라진 것에만 붙는다. "모르겠다" 는 정직한 답으로 남는다.

**주지 않는 것**: 이 비교는 **두 시점의 스냅샷** 비교다. 그 사이 파일이 바뀌었을 수 있다. 감시(watch) 루프가 아니다 — 지속 감시는 "재실행 없음" 계약과 충돌한다. 그 사이 무슨 일이 있었는지는 **지문이 아니라 별도의 기록**이 필요하다.

## 대안

- **행 인덱스로 비교 (기각)**: 순서가 바뀌면 전부 "변경"으로 보고된다. 정렬이 흔한 파서에서 쓸 수 없다.
- **전체 내용 해시로 비교 (기각)**: 값 하나가 바뀌면 무엇이 바뀌었는지 알 수 없다. "무엇이 빠졌나" 를 묻는 도구가 아니다.
- **불완전해도 있는 것만 비교 (기각)**: 부분 결과를 완전한 결과처럼 보여준다 — 거짓 삭제가 그대로 생긴다.
- **LLM 으로 비교 (기각)**: 결정론이 깨진다. 같은 입력이 같은 답을 주지 않는다. 비교 도구가 **판정**을 하는 이상 결정론이 contract 다.

## 결과

- `compare_results` 는 `comparable`, `refusals`(사유·무시한 차이), `added`, `removed`, `changed`, `unchanged_count`, `ignored_fields`, `partial`, `key_conflicts` 를 담는다.
- 필드 변화에는 이전·현재 **근거 포인터**가 붙는다 — 어디서 바뀌었는지 추적할 수 있다.
- 허용하지 않은 비교(strict 위반, 미보관 결과, 중복 identity)는 사유와 함께 거절된다.
- 비교는 언제나 **읽기**다. 실행 대상이 아니다.
